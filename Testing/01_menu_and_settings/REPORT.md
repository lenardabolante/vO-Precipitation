## What `--selftest` / `--selftest-ui` do not cover

Covered by them: new, save, leave, load, autosave, a failed save, a save that is never answered, rename, duplicate, delete, a region preset, the three other modes starting, quit while running, the panels, pause.

Not covered by them, covered here by the harness: every world size and terrain / settlements kind through the real launch path; start month and time of day arriving in the first frame; every setting persisting; old, out-of-range and damaged `settings.json`; each kind of broken slot; loading from `state.sav.bak`; a state file the simulation refuses; a simulation killed mid-game; the background image cases.

Still not covered by anything: the file chooser and drag-and-drop for backgrounds, fullscreen on a real display, typing with a real keyboard, `--load` / `--new` through a real window.

## Bugs found and fixed

1. **Selected "Auto" month drawn "Au…".** Root cause: 13 cells of 33 px and the selected cell uses the bold font. `Ui.java` `seg()` (+2 lines): a selected label that does not fit in bold stays in the regular weight. Before `05_ui_new_1680x760_before_fix.png`; after `05_ui_new_1680x760.png`.
2. **Region hint cut off before the biome** ("… of Washington · temperate b…"). `NewSimScreen.java` `paint()`: a shorter sentence when the long one does not fit ("Real terrain and starting climate of Washington · temperate biome."). Before `06_ui_new_region_min1024x581_before_fix.png`; after `06_ui_new_region_min1024x581.png`. The longest names ("Antarctica (McMurdo Sound)") still end in an ellipsis.
3. **Writes of `settings.json` / `meta.json` / state files failed now and then.** Measured: 32 and 60 of 3000 temp-file moves refused with `AccessDeniedException`. Root cause: one attempt, no retry. `SaveStore.java` `moveInto()`: up to five retries, 10–160 ms apart. After: 0 of 3000, twice. A failed settings write was only logged, so a changed setting could be lost silently.
4. **Error screen said "Your last save of X is intact" for a save the simulation had just refused.** `AppShell.java` `simProblem()` (SHARED, 1 line → 4). Before / after: `45_error_screen_real_corrupt_state_file_before_fix.png` / `45_error_screen_real_corrupt_state_file.png`. (A leftover toast from the previous harness step is visible at the top of the "after" picture; it is not part of the error screen.)
5. **`--print-keys` listed the arrow keys as "?"** on a Windows console. `Main.java` (SHARED): `console()` writes Left / Right / Up / Down and plain dashes when the output encoding cannot show the symbols.
6. **A bad or missing option value ended in a Java stack trace.** `Main.java` (SHARED): the argument switch is wrapped; "[viewer] --frames: not a valid value (…). See --help.", exit 2.

## Bugs found and not fixed

1. **Hurricane Formation and Cloud Formations do not remember the last chapter / stage / tab** (`HurricaneScreen.java:37` `chapter` starts at 0; `MainMenuScreen.java:36` `cloudType` starts at 0; PLAN.md line 353). The storage was added in `Settings.java`: `hurricaneChapter` (int), `hurricaneExplore` (boolean), `hurricaneStage` (String), `hurricaneView` (String), `showcaseType` (String), written as a `"modes"` block; a file without it loads with defaults (verified). The screens belong to other areas, so they are not wired.
2. **The slot card prints "Folder: saves/<id>" whatever the saves folder is** (`MainMenuScreen.java`, seen in `42_…png`). Wrong only with `--saves-dir`; shared file, cosmetic.

## Things that look questionable but are design choices

1. A slot whose state file is garbage but not empty looks playable in the list; only starting it shows the error screen (`SaveStore.read` checks size only).
2. Leaving the error screen of a damaged slot keeps the slot; the player deletes it by hand.
3. `--clear-background` / "Use default sky" leaves the copied picture in `<config>/backgrounds/`.
4. An old `settings.json` that had T or K on other actions leaves the newer "Trigger a tornado" and "Toggle climate panel" unbound rather than taking the keys back; the Controls page says "No key: …".
5. `--set-background` with a bad file exits 0 when `--ui-snapshot` follows it (the snapshot's exit code wins).
6. Unknown arguments are ignored with one line rather than refused.
